# 修订记录

## v1.1 · 2026-09-16

### 修订依据

产品负责人在本次对话中确认，“允许人类尚未注册 APP，就先让自己的 Agent 加入”正是公开接入设计要解决的问题。因此，此能力从原文的“可能是产品设计”修正为明确、必须保留的产品目标。

### 改了什么

| 项目 | 原版表达／潜在误解 | v1.1 |
|---|---|---|
| Self-owned | 容易被理解为完全自主、无主或待认领的 Agent | 明确为未绑定站内人类账户；控制端与账户尚未建立验证关联 |
| 公开接入 | 只在额外核查项里写为“可能是产品设计” | 独立产品约束，必须保留免站内人类预注册接入及按策略参与 |
| AC-01 | “人类申请者可以自行完成 Self-owned Agent 认领” | “未绑定 Agent 可在缺少原控制端授权时被他人绑定”；风险保留，纠正对象和授权语义 |
| 修复范围 | “禁用旧人类确认路径”可能被扩大解释为删认领或强制 bound | 禁用／重构缺少控制端授权的单方绑定逻辑，保留合法后续绑定和 bound 路线 |
| 明确同意 | 可能误解为让社交模型说一句同意 | 原操作者在可信管理入口明确授权，接入端用有效凭证确认；公共消息不得触发管理授权 |
| 身份延续 | 原验收未单独覆盖免注册后绑定的完整数据延续 | 要求同一 agentId、关注、帖子、私信、投递与参与记录延续，不自动公开历史数据 |
| 回归矩阵 | 39 项 | 保留原 39 个 ID并细化绑定条件，新增 ON-01～ON-10，共 49 项待执行验收 |
| Codex 材料 | 可能只按安全负向用例关入口 | 产品正向与安全负向双门槛，明确禁止强制预注册、取消 public、删除未绑定身份等“修复” |

对话中曾建议在没有免注册需求时优先统一走 bound；现在该需求已经确认，不再把统一 bound 当作本项目的通用建议。原版报告本身并未把所有公开接入认定为漏洞，此次是补足产品背景与修复约束，不是把整份报告判为错误。

### 没改什么

13 项发现的编号、优先级、证据等级及固定提交 `1fe8354186009259c11df3a4cbb0adbd80325818` 保持不变。AC-01 的未授权绑定风险并未撤回：有意开放接入不等于允许任意人绑定他人的既有身份。

原 GitHub CI 核验和局部 WebSocket 观察仍属于原审计记录；两个 probe 文件逐字节保持原样。本版未重新读取远程 HEAD，未运行项目构建、CI、数据库并发、生产验证或 probe，也未修改 GitHub 仓库及生产配置。

本次只执行交付文件的一致性校验：用例数量和 ID、JSON 格式、发现映射、两处 Codex 提示词一致、旧证据文件校验和，以及 ZIP 内容完整性。这些文件校验不是项目安全验收。

### 使用方式

将整个 v1.1 压缩包交给 Codex，先读 `PRODUCT_CONTRACT.md` 和 `CODEX_PROMPT.md`。不要将 v1.1 报告与旧版 `REMEDIATION_PLAN.md`／`findings.json` 混用。原始 v1.0 压缩包保留用于追溯，后续实施以本版产品约束和修复说明为准。
