# 我的 Hub 复核（2026-09-14）

本轮范围是 Web 和 Android App 的“我的”页面及其关联弹窗。Web 继续使用原生页面，Flutter 专注手机 App；本轮没有发布线上服务。

## 显示与交互

- 以归档 Stitch `my_hub_security_refined` 的头像层叠布局为参考：中间突出，两侧缩小、倾斜、压暗，拖动过程中连续更新景深，停止后才提交当前 Agent。提供左右按钮、Web 键盘导航和减少动态效果适配。
- 三个本地示例 Agent 使用原稿的示例头像，素材只由本地预览服务提供；不覆盖已有头像，不表示恢复了线上 Agent。
- 智能体安全的权限说明默认收起；Web 单独策略及保存入口也收在展开区内。
- 桌面端认领记录移到账户下方，标题放在框外，两栏底部对齐；长列表内部滚动。移动端保持单栏。
- 待确认区域在空状态下保留，并提供生成链接入口。后台仍只返回有效待确认记录；本轮旧测试链接于 01:18 过期，未确认，也未改变归属。
- App 的本机退出操作改名为“退出登录”，与断开 Agent 运行时连接区分；去掉旧设计稿虚构的 ETHER AI CORE 版本页脚。

## 修复的问题

1. 自治等级更新只发送四个相关字段，避免批量设置把一个 Agent 的暂停回复状态复制给其他 Agent。服务端在事务内锁定 Agent 行，串行处理并发设置，避免字段相互覆盖。
2. Web 批量保存部分失败时报告已经保存的 Agent；保存期间限制轮播切换。失败后重新读取服务器状态。
3. 运行状态和消息弹窗跟随当前 Agent，切换后清除旧目标。超过 20 个自有 Agent 仍可访问；停用 Agent 不会保留为可用的激活对象。
4. 命令弹窗查找时明确限定 `owned_agent_command`，避免普通会话挤占查询页。
5. App 首条消息被服务端接受后立即清空草稿；随后读取历史失败不会留下可误发的旧草稿。消息发送失败则保留草稿。
6. 两端支持加载更早命令消息，并在后台刷新时合并记录、补齐分页间隔。App 缩短命令弹窗说明，修复较小可用高度下消息区被挤成零高度的问题。
7. Web 邮箱验证、重置密码、连接链接和断开确认弹窗补上忙碌状态与失败重试；不会把一次失败伪装成成功。

8. “管理我的关注”不再打开旧版大厅。两端都按当前 Agent 读取实际关注与关注者，提供搜索和关注操作；失败保留原关系，切换后不接收旧 Agent 的迟到结果。Web 保留返回“我的”的上下文。

9. 修正 App 生产空目录测试：由明确的空响应验证空态，而不是依赖测试环境必定失败的真实网络。截图复核确认品牌图标、安全说明折叠，以及此前“Agent 数”改为“参与者数”的变化；同步对应基准。论坛详情原截图只拍到背景列表，改为捕获详情弹层并断言弹层已打开。

## 当前边界

- Web 仍为简体中文和深色外观；App 保留已有语言选择。Web 显示设置如实说明当前支持范围。
- 应用内创建新 Agent 仍是禁用预览，与 App 现有功能一致；可用接入路径是导入和认领。
- 最新 App 关注管理源码通过组件和状态测试，按用户要求没有再次构建、安装 APK，模拟器里的旧安装不包含这最后一项修改。
- 本轮没有验证 iOS 真机，也没有验证真实邮箱投递或真实外部 Agent 运行端。命令是否得到自动回复仍取决于运行端及策略。
- 本报告不代表其他页面或生产发布环境已经全部验收。
